> **Revised 2026-05-09:** Fly Postgres pivoted to **Neon Postgres** (free, external). Reason: Fly Unmanaged Postgres deprecated/unsupported; Fly Managed Postgres minimum $38/mo. ## Key Insights

- **No production data exists yet** — smoke was deferred, so the SQLite `Session` table is empty/sparse. Migration is essentially a fresh schema apply, not a data dump+restore.
- **Fly.io free tier** runs 3 small VMs free + 3GB Postgres. Sufficient for single-store admin with light traffic.
- **App auto-suspend** on Hobby may cause first-request cold start (~5s). Acceptable for monthly-cadence admin use.
- **Local dev can stay on SQLite** for fast iteration, with Postgres only in production. Heterogeneous setup is supported by Prisma; keeps `pnpm dev` lightweight.

## Requirements

### Functional
- Prisma schema runs on Postgres
- Fly.io app deployed at `<app-name>.fly.dev`
- App responds to HTTPS requests
- `shopify.app.toml` `application_url` updated to Fly URL
- `shopify app deploy` registers new URL with Partner

### Non-functional
- Fly.io secrets (env vars) configured: `SHOPIFY_API_KEY`, `SHOPIFY_API_SECRET`, `DATABASE_URL`, `SHOPIFY_APP_URL`, `SCOPES`, optional `SHOP_CUSTOM_DOMAIN`
- Build artifact size <250MB
- Cold start <10s

## Implementation Steps

1. **Decide DB strategy**
   - Recommended: SQLite local + Postgres production (heterogeneous, simpler local dev)
   - Alternative: Postgres everywhere (homogeneous, requires local Postgres install or Docker)
   - **Decision point:** if user prefers homogeneous, install local Postgres or use Docker; otherwise heterogeneous

2. **Update Prisma schema**
   - For heterogeneous: keep `provider = "sqlite"` in `prisma/schema.prisma` for local; production overrides via env var (Prisma supports this via `datasource db { provider = env("DATABASE_PROVIDER") }`)
   - For homogeneous: change provider to `postgresql` everywhere
   - Test: `pnpm prisma generate` — clean

3. **Generate Postgres migrations**
   - Heterogeneous: `DATABASE_URL=postgres://... pnpm prisma migrate dev --name init` — creates migration files compatible with Postgres
   - Homogeneous: regenerate all migrations against Postgres

4. **Create Dockerfile**
   - Use Fly.io Remix template Dockerfile (`flyctl launch --no-deploy` generates one)
   - Multi-stage: deps → build → runtime
   - Base: `node:20-alpine` or `node:22-alpine`
   - Run: `pnpm setup && pnpm start` (where setup runs `prisma migrate deploy`)

5. **Provision Fly.io app + Postgres**
   - `flyctl auth login` (if not authed)
   - `flyctl launch --no-deploy --name dopamiles-bundle-app` (or similar)
     - Region: closest to Dopamiles customers (e.g., `sin` Singapore, `iad` US East, `ord` US Central)
     - Postgres: yes, attach Hobby tier
     - Redis: no
   - Note generated `<app>.fly.dev` URL
   - Verify `fly.toml` generated correctly

6. **Configure Fly secrets**
   - `flyctl secrets set SHOPIFY_API_KEY=<from .env>`
   - `flyctl secrets set SHOPIFY_API_SECRET=<from .env>`
   - `flyctl secrets set SCOPES=<from shopify.app.toml>`
   - `flyctl secrets set SHOPIFY_APP_URL=https://<app>.fly.dev`
   - `DATABASE_URL` is auto-set by Fly Postgres attachment
   - Verify: `flyctl secrets list`

7. **First deploy**
   - `flyctl deploy`
   - Monitor logs: `flyctl logs`
   - Expect: build → migrate → app start
   - Verify HTTP 200 on `https://<app>.fly.dev/healthcheck` (if route exists) or root URL

8. **Update shopify.app.toml**
   - Edit `application_url = "https://<app>.fly.dev"`
   - Save and commit

9. **Register URL with Partner**
   - `shopify app deploy` — pushes `shopify.app.toml` config to Partner dashboard
   - Verify in Partner UI: app's URLs reflect Fly URL
   - Verify `client_id` UNCHANGED in `shopify.app.toml`

10. **Sanity test from prod URL**
    - Direct HTTPS GET to `https://<app>.fly.dev/auth/login` — should render login page
    - Don't yet install on Dopamiles store — that's Phase 04

11. **Commit**
    - `git add -A`
    - `git commit -m "feat(deploy): migrate to Postgres + deploy to Fly.io free tier"`
    - Add `Dockerfile`, `.dockerignore`, `fly.toml`, updated `shopify.app.toml`, Prisma migration changes

## Security Considerations

- Fly secrets MUST hold `SHOPIFY_API_SECRET` — never commit to git
- `.env` excluded from `.dockerignore` (don't bake into image)
- HTTPS enforced by Fly.io (default)
- Postgres connection uses Fly internal network (encrypted)
- `client_id` is NOT a secret (public) but `client_secret` IS
